## 引言

历史上，快速JIT编译是一门"黑魔法"。要编写一个快速JIT编译器，你需要精通汇编语言。这也是为什么至今没有生产级数据库拥有自己的JIT编译器——它们要么依赖LLVM，要么生成C/C++代码，两者都受限于高编译时间。

但现在，AI改变了这一切。[pgrust](https://github.com/malisper/pgrust)项目证明：借助AI辅助，我们可以在**5微秒**内完成JIT编译，实现10-20倍的性能提升。

## 什么是JIT编译？

JIT（Just-In-Time）编译是在运行时动态生成机器码的技术。当使用得当时，它可以带来**2-5倍甚至更高的性能提升**。

核心应用场景：

- **编程语言解释器**：在运行时接收代码并即时编译
- **正则表达式引擎**：根据具体模式生成优化代码
- **数据库查询**：为每个SQL查询生成定制的机器码
- **数据解析**：在运行时才知道数据schema的场景

## 实战：5μs内构建正则表达式引擎

让我们用一个简单的正则表达式引擎来演示JIT编译的威力。

### 第一步：定义正则表达式AST

```rust
enum Node {
    Literal(&'static str),
    Concatenation(Box<Node>, Box<Node>),
    Repetition(Box<Node>),
}

fn literal(text: &'static str) -> Node {
    Node::Literal(text)
}

fn concatenation(left: Node, right: Node) -> Node {
    Node::Concatenation(Box::new(left), Box::new(right))
}

fn repetition(body: Node) -> Node {
    Node::Repetition(Box::new(body))
}
```

### 第二步：实现解释器（作为基准）

```rust
fn match_node(node: &Node, input: &[u8], pos: usize, 
              next: &dyn Fn(usize) -> bool) -> bool {
    match node {
        Node::Literal(text) => {
            let literal = text.as_bytes();
            input[pos..].starts_with(literal) && next(pos + literal.len())
        }
        Node::Concatenation(left, right) => {
            match_node(left, input, pos, &|left_end| {
                match_node(right, input, left_end, next)
            })
        }
        Node::Repetition(body) => {
            match_node(body, input, pos, &|body_end| {
                match_node(node, input, body_end, next)
            }) || next(pos)
        }
    }
}
```

解释器简洁但慢。对于 `b(an)*` 这样的模式，解释器比手写代码慢**10-20倍**。

### 第三步：JIT编译的核心——Copy-and-Patch

JIT编译的关键思想是**模板化**。我们为每种操作预定义汇编模板（stencil），运行时只需填充具体参数：

```rust
// 字符比较模板
fn stencil_char(byte: u8, stencil_pos: usize, fail_pos: usize) -> [u32; 4] {
    [
        0x39400009,                                                 // ldrb w9, [x0]
        0x7100013F | ((byte as u32) << 10),                         // cmp  w9, #byte
        0x54000001 | cond_branch_offset(stencil_pos + 2, fail_pos), // b.ne fail
        0x91000400,                                                 // add  x0, x0, #1
    ]
}

// 重复结构模板（回溯）
fn stencil_split(resume_addr: u64) -> [u32; 5] {
    [
        0xD2800009 | addr_bits(resume_addr, 0), // movz x9, #addr[0..16]
        0xF2A00009 | addr_bits(resume_addr, 1), // movk x9, #addr[16..32], lsl 16
        0xF2C00009 | addr_bits(resume_addr, 2), // movk x9, #addr[32..48], lsl 32
        0xF2E00009 | addr_bits(resume_addr, 3), // movk x9, #addr[48..64], lsl 48
        0xA8810029,                             // stp  x9, x0, [x1], #16
    ]
}
```

### 第四步：生成可执行代码

```rust
use std::mem;

type MatchFn = unsafe extern "C" fn(input: *const u8, bstack: *mut u64) -> u64;

struct Jit {
    buf: *mut u32,
    nbytes: usize,
}

impl Jit {
    fn compile(regex: &Node) -> Jit {
        // 1. 生成机器码
        let code = generate_code(regex);
        
        // 2. 分配可执行内存（macOS需要特殊处理W^X）
        unsafe {
            let buf = libc::mmap(
                std::ptr::null_mut(),
                code.len() * 4,
                libc::PROT_READ | libc::PROT_WRITE | libc::PROT_EXEC,
                libc::MAP_PRIVATE | libc::MAP_ANON | libc::MAP_JIT,
                -1, 0,
            ) as *mut u32;
            
            // 3. 写入代码
            pthread_jit_write_protect_np(0);
            std::slice::from_raw_parts_mut(buf, code.len())
                .copy_from_slice(&code);
            pthread_jit_write_protect_np(1);
            
            Jit { buf, nbytes: code.len() * 4 }
        }
    }
    
    fn is_match(&mut self, input: &[u8]) -> bool {
        unsafe {
            let matcher: MatchFn = mem::transmute(self.buf);
            matcher(input.as_ptr(), /* stack */ ) != 0
        }
    }
}
```

## AI如何改变JIT编译

传统上，编写JIT编译器需要：
1. 精通汇编语言
2. 理解CPU微架构
3. 处理各种边界情况

AI辅助开发的优势：

- **降低门槛**：AI可以处理底层汇编细节
- **快速迭代**：从概念到原型只需几小时
- **质量保证**：AI可以帮助识别潜在的性能陷阱

pgrust项目的作者表示：

> "我个人在汇编方面的经验仅限于完成microcorruption CTF。我从未真正自己写过汇编代码。有了AI，我可以给出JIT编译器的大致框架，它能帮我处理很多细节。"

## 实际应用：pgrust

pgrust是一个用Rust重写的PostgreSQL，其JIT编译器可以：

- **5μs内编译每个SQL查询**（而非只编译一部分）
- **10-100倍的分析查询加速**
- **完全兼容PostgreSQL生态**

这意味着每个查询都能获得定制的机器码优化，而传统数据库只能对少数查询进行JIT优化。

## 避坑清单

| 问题 | 原因 | 解决方案 |
|-----|------|---------|
| macOS上代码无法执行 | W^X保护机制 | 使用 `pthread_jit_write_protect_np` |
| JIT编译比解释器还慢 | 模板设计不当 | 优化stencil，减少指令数 |
| 分支预测失败率高 | 跳转地址计算错误 | 使用相对偏移而非绝对地址 |
| 内存泄漏 | 忘记释放mmap | 实现Drop trait |
