HTTP 是「一问一答」的：客户端发起请求，服务器返回响应，连接就结束了。但很多场景需要**服务器主动推数据**——聊天消息、股票行情、在线协作、游戏对战。用 HTTP 轮询？太浪费且不及时。

**WebSocket** 提供全双工（双向）通信：连接建立后，客户端和服务器可以随时互相发消息，延迟低至毫秒级。

## 第一章：WebSocket 与 HTTP 的关系

**WebSocket 不是取代 HTTP，而是借 HTTP 升级而来：**

```text
1. 客户端先发一个普通的 HTTP 请求
   GET /chat HTTP/1.1
   Upgrade: websocket
   Connection: Upgrade
   Sec-WebSocket-Key: x3JJHMbDL1EzLkh9GBhXDw==

2. 服务器同意升级，返回 101 状态码
   HTTP/1.1 101 Switching Protocols
   Upgrade: websocket
   Connection: Upgrade
   Sec-WebSocket-Accept: HSmrc0sMlYUkAGmm5OPpG2HaGWk=

3. 之后连接升级为 WebSocket，双向自由收发
```

**HTTP 轮询 vs WebSocket：**

```text
HTTP 轮询（旧方式）：
  客户端 → 有消息吗？ → 服务器 → 没有
  客户端 → 有消息吗？ → 服务器 → 没有
  客户端 → 有消息吗？ → 服务器 → 有！（浪费 90% 请求）

WebSocket：
  连接建立后，服务器主动推：
  服务器 → 新消息！
  服务器 → 又来一条！
  服务器 → 用户上线了！
```

## 第二章：服务端实现（Node.js + ws）

```bash
mkdir chat-server && cd chat-server
npm init -y
npm install ws
```

```javascript
// server.js
const { WebSocketServer } = require('ws');

// 创建 WebSocket 服务器，监听 8080 端口
const wss = new WebSocketServer({ port: 8080 });

// 客户端连接
wss.on('connection', (ws, req) => {
  // 给连接分配用户名
  const username = `用户${Math.floor(Math.random() * 1000)}`;
  ws.username = username;
  ws.isAlive = true;

  // 广播上线消息
  broadcast({
    type: 'system',
    text: `${username} 加入了聊天室`,
    online: wss.clients.size,
  });

  // 接收消息
  ws.on('message', (data) => {
    const message = data.toString();
    console.log(`[${username}] ${message}`);

    // 处理 JSON 消息
    try {
      const parsed = JSON.parse(message);
      handleMessage(ws, parsed);
    } catch {
      // 普通文本，广播
      broadcast({
        type: 'chat',
        username,
        text: message,
      });
    }
  });

  // 连接关闭
  ws.on('close', () => {
    broadcast({
      type: 'system',
      text: `${username} 离开了聊天室`,
      online: wss.clients.size,
    });
  });
});

// 处理结构化消息（私聊、心跳等）
function handleMessage(ws, msg) {
  switch (msg.type) {
    case 'private':
      // 私聊：找到目标用户发送
      sendToUser(msg.to, {
        type: 'private',
        from: ws.username,
        text: msg.text,
      });
      break;
    case 'ping':
      // 心跳
      ws.isAlive = true;
      ws.send(JSON.stringify({ type: 'pong' }));
      break;
  }
}

// 广播给所有客户端
function broadcast(data) {
  const payload = JSON.stringify(data);
  wss.clients.forEach((client) => {
    if (client.readyState === 1) {
      client.send(payload);
    }
  });
}

// 给指定用户发消息
function sendToUser(username, data) {
  wss.clients.forEach((client) => {
    if (client.username === username && client.readyState === 1) {
      client.send(JSON.stringify(data));
    }
  });
}

// 心跳检测：每 30 秒检查连接是否还活着
const heartbeat = setInterval(() => {
  wss.clients.forEach((ws) => {
    if (!ws.isAlive) {
      return ws.terminate(); // 死连接直接掐断
    }
    ws.isAlive = false;
    ws.ping(); // 主动 ping，触发 pong 回调
  });
}, 30000);

// 清理定时器
process.on('SIGINT', () => {
  clearInterval(heartbeat);
  wss.close();
});
```

## 第三章：客户端实现（原生 WebSocket）

```html
<!DOCTYPE html>
<html lang="zh">
<head>
  <meta charset="UTF-8" />
  <title>实时聊天室</title>
</head>
<body>
  <h2>实时聊天室</h2>
  <div id="messages" style="height: 300px; overflow-y: auto; border: 1px solid #ccc;"></div>

  <form id="form">
    <input id="input" placeholder="输入消息..." />
    <button type="submit">发送</button>
  </form>

  <script>
    const messagesEl = document.getElementById('messages');
    const form = document.getElementById('form');
    const input = document.getElementById('input');

    // 建立 WebSocket 连接
    const ws = new WebSocket('ws://localhost:8080');

    // 连接建立
    ws.onopen = () => {
      append('system', '已连接到服务器');
      // 启动心跳
      setInterval(() => {
        if (ws.readyState === WebSocket.OPEN) {
          ws.send(JSON.stringify({ type: 'ping' }));
        }
      }, 25000);
    };

    // 收到消息
    ws.onmessage = (event) => {
      const data = JSON.parse(event.data);
      switch (data.type) {
        case 'chat':
          append('chat', `${data.username}: ${data.text}`);
          break;
        case 'system':
          append('system', `[系统] ${data.text}`);
          break;
        case 'private':
          append('private', `[私聊] ${data.from}: ${data.text}`);
          break;
      }
    };

    // 连接断开（触发重连）
    ws.onclose = () => {
      append('system', '连接断开，3 秒后重连...');
      setTimeout(connect, 3000);
    };

    // 连接错误
    ws.onerror = (error) => {
      append('system', '连接出错');
    };

    // 发送消息
    form.addEventListener('submit', (e) => {
      e.preventDefault();
      const text = input.value.trim();
      if (!text) return;

      // 私聊语法：@用户名 消息
      const match = text.match(/^@(\S+)\s+(.+)/);
      const payload = match
        ? { type: 'private', to: match[1], text: match[2] }
        : { type: 'chat', text };

      ws.send(JSON.stringify(payload));
      input.value = '';
    });

    // 辅助：追加消息到页面
    function append(kind, text) {
      const div = document.createElement('div');
      div.style.color = kind === 'system' ? '#888' : '#222';
      div.textContent = text;
      messagesEl.appendChild(div);
      messagesEl.scrollTop = messagesEl.scrollHeight;
    }
  </script>
</body>
</html>
```

## 第四章：心跳机制（Heartbeat）

WebSocket 没有内置「超时」，连接可能半死不活（TCP 假死）。**心跳机制**是必须的：

```text
服务器每 30 秒：ws.ping()
客户端收到 ping 自动回 pong（协议层自动，不需要手动处理）
服务器若 30 秒没收到 pong → 判定死连接 → 掐断

作用：
1. 识别假死连接，及时释放资源
2. 防止中间代理（Nginx、负载均衡）因空闲超时关闭连接
```

**Nginx 上也有对应配置（如果用了反向代理）：**

```nginx
server {
    listen 443 ssl;
    server_name chat.example.com;

    location /ws/ {
        proxy_pass http://backend:8080;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;     # 关键：WebSocket 升级
        proxy_set_header Connection "upgrade";      # 关键
        proxy_set_header Host $host;

        proxy_read_timeout 300s;                    # 超过默认 60s 防止掐断
        proxy_send_timeout 300s;
    }
}
```

## 第五章：断线重连与消息可靠性

**客户端自动重连（加指数退避）：**

```javascript
let reconnectAttempts = 0;

function connect() {
  const ws = new WebSocket('ws://localhost:8080');

  ws.onopen = () => {
    reconnectAttempts = 0;
    console.log('已连接');
  };

  ws.onclose = () => {
    // 指数退避：1s, 2s, 4s, 8s...最多 30s
    const delay = Math.min(1000 * Math.pow(2, reconnectAttempts), 30000);
    reconnectAttempts++;
    setTimeout(connect, delay);
  };
}

connect();
```

**消息可靠性策略：**

```text
实时聊天：丢了就算了（最多补拉历史）
重要消息：需要 ack 确认机制
  客户端发送 → 服务器存储并返回 { id } 
  客户端超时未确认 → 自动重发
  接收方去重（按消息 id）
```

## 第六章：性能与扩展

**一个 Node.js 进程能撑多少连接？**

```text
单个 ws 服务器：约 5 万~10 万并发连接（取决于机器内存）
内存估算：每个 WebSocket 连接约 20~30KB（缓冲 + 上下文）

要撑更大：水平扩展
  多个 ws 服务器节点 + Redis Pub/Sub 广播
  客户端通过负载均衡（Nginx / HAProxy）连接
```

**多节点广播架构：**

```text
客户端A ──► ws节点1 ──┐
                       ├──► Redis Pub/Sub ──► ws节点2 ──► 客户端B
客户端C ──► ws节点2 ──┘
```

## 避坑清单

| 坑 | 正确做法 |
|----|---------|
| 忘了配置代理升级头 | Nginx 必须加 `Upgrade` / `Connection` 头，否则握手失败 |
| 空闲连接被代理掐断 | 心跳保活 + 调大 `proxy_read_timeout` |
| `wss://` 用 `ws://` 地址 | HTTPS 页面必须用 `wss://`，否则浏览器拒绝 |
| 生产环境裸连 WebSocket | 用 `wss://`（TLS），明文 ws 会被运营商劫持 |
| 广播时遍历 `readyState` | 发送前判断 `client.readyState === OPEN(1)` |
| 服务器死连接堆积 | 心跳机制 + `ws.terminate()` 掐死假死连接 |
| 私聊找不到用户 | 维护 username→ws 的映射表，下线时删除 |
| 客户端重连风暴 | 指数退避（1s→2s→4s…）而不是固定 1s |
| 大消息阻塞事件循环 | 设置 `maxPayload` 限制（如 1MB），超限断连 |
| 忘了 `JSON.stringify` | send 只接受字符串或 Buffer，对象要先序列化 |
| 发送二进制没处理 | 用 `ws.binaryType = 'arraybuffer'` 按需处理 |
| 旧浏览器兼容 | 加 `socket.io` 兜底（支持轮询降级），现代浏览器无需 |

## 小结

```text
本质：HTTP 升级来的双向长连接
握手：Upgrade + 101 Switching Protocols
服务端：ws 库，connection/message/close 三大事件
客户端：new WebSocket()，onopen/onmessage/onclose
保活：ping/pong 心跳，Nginx 开 upgrade 头
可靠性：重连退避 + 消息 ack + 去重
扩展：Redis Pub/Sub 跨节点广播
```

WebSocket 并不神秘——它只是「升级版的 HTTP 连接」。你已经能写出一个可用的聊天室，并且知道了心跳、重连、扩展这些生产级要点。

下一步可以探索：`socket.io`（内置重连/房间/ack）、`Server-Sent Events`（SSE，单向推送更简单）、以及 WebTransport（更新的传输协议）。选择取决于需求——需要双向实时通信就 WebSocket，只需要服务器推流 SSE 更省事。
