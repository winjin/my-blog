## 引言

作为开发者，终端是我们每天接触最多的工具之一。然而，原生终端的功能往往有限——开多个窗口太乱、SSH 断开就丢会话、没有分屏功能……于是各种终端复用器（Terminal Multiplexer）应运而生。

本文将深入对比五款主流终端工具：**iTerm2**、**tmux**、**cmux**、**otty** 和 **Muxy**，帮你找到最适合自己的那一个。

## 什么是终端复用器？

终端复用器可以在一个终端窗口中创建多个"虚拟终端"，支持分屏、标签页、会话保持等功能。核心价值：

- **多任务并行**：同时查看日志、写代码、跑测试
- **会话持久化**：SSH 断开后恢复工作现场
- **远程协作**：共享终端会话给同事
- **工作流定制**：一键启动预设的窗口布局

## 五款终端工具对比

### 1. iTerm2 — macOS 终端的王者

![iTerm2 界面](https://images.unsplash.com/photo-1629654297299-c8506221ca97?w=800&h=400&fit=crop)

**特长：**

- **原生体验**：macOS 原生应用，性能流畅，启动秒开
- **搜索功能强大**：支持正则搜索，可高亮匹配结果
- **自动补全**：内置历史命令补全、文件路径补全
- **分屏简单**：Cmd+D 横分，Cmd+Shift+D 竖分，上手极快
- **Profile 系统**：可为不同项目保存不同的窗口配色、字体、工作目录
- **触控板手势**：三指捏合切换全屏，双指滑动切换标签
- **热键窗口**：一键呼出半透明终端（类似 Quake 风格）
- **Shell Integration**：自动标记命令开始/结束位置，点击跳转

**缺陷：**

- **仅限 macOS**：Linux/Windows 用户无法使用
- **内存占用**：相比原生 Terminal.app 更吃内存
- **SSH 会话恢复有限**：断线重连不如 tmux 彻底
- **免费但不开源**：功能迭代由少数维护者决定

**适用场景**：macOS 日常开发、轻量级前端/后端开发

### 2. tmux — 终端复用器的瑞士军刀

![tmux 分屏效果](https://images.unsplash.com/photo-1518432031352-d6fc5c10da5a?w=800&h=400&fit=crop)

**特长：**

- **会话持久化**：SSH 断线后 `tmux attach` 一秒恢复，这是杀手级功能
- **分屏灵活**：上下、左右自由切割，支持调整比例
- **窗口/面板/会话三层管理**：组织复杂工作流
- **脚本化**：可通过配置文件和脚本一键启动预设布局
- **插件生态**：tpm（tmux plugin manager）提供丰富插件
  - tmux-resurrect：保存/恢复会话
  - tmux-continuum：自动定期保存
  - tmux-sensible：合理默认配置
- **跨平台**：Linux、macOS、WSL 均可使用
- **轻量级**：纯终端运行，无 GUI 依赖

**缺陷：**

- **学习曲线陡峭**：默认键绑定反直觉（Ctrl+B 前缀）
- **中文显示问题**：某些字体/终端下中文乱码
- **滚动不便**：需要进入复制模式才能滚动历史
- **配置复杂**：.tmux.conf 语法晦涩，新手容易迷失
- **复制粘贴**：与系统剪贴板不互通，需要额外配置

**适用场景**：远程服务器开发、需要稳定会话的 DevOps/SRE 工作

**基础配置示例：**

```bash
# ~/.tmux.conf
set -g prefix C-a
unbind C-b
set -g mouse on
set -g default-terminal "screen-256color"
set -g history-limit 10000

# 分屏快捷键
bind | split-window -h
bind - split-window -v
```

### 3. cmux — tmux 的现代化封装

**特长：**

- **简化 tmux**：在 tmux 之上提供更友好的命令行接口
- **一键启动**：`cmux` 命令直接创建带预设布局的会话
- **自动检测项目**：根据目录自动选择合适的窗口配置
- **与 tmux 完全兼容**：底层还是 tmux，所有 tmux 插件可用
- **更好的默认值**：开箱即用的鼠标支持、状态栏美化

**缺陷：**

- **额外依赖**：需要先安装 tmux
- **功能有限**：只是 tmux 的包装，核心能力无突破
- **社区小**：生态不如 tmux 丰富
- **维护不确定**：项目活跃度需要关注

**适用场景**：想用 tmux 但嫌配置麻烦的开发者

### 4. otty — 基于 Rust 的新锐终端

**特长：**

- **现代架构**：用 Rust 编写，内存安全且性能出色
- **GPU 加速渲染**：OpenGL 渲染，滚动流畅
- **高度可定制**：支持 Lua 脚本配置
- **内置终端复用**：分屏、标签页原生支持
- **Wayland 原生**：Linux 新一代显示协议支持

**缺陷：**

- **生态不成熟**：相比 iTerm2/tmux，插件和主题稀缺
- **文档不足**：学习资源有限
- **平台支持有限**：主要面向 Linux，macOS/Windows 支持不稳定
- **配置语法特殊**：Lua 配置对新手不友好

**适用场景**：喜欢尝鲜的 Linux 开发者，追求极致性能

### 5. Muxy — 新兴的终端协作工具

**特长：**

- **会话共享**：核心卖点，支持多人实时共享终端
- **权限控制**：可设置只读/读写权限，保护生产环境
- **录制回放**：支持录制终端会话用于教学/审计
- **Web 界面**：浏览器即可访问，无需安装客户端
- **团队协作**：适合远程团队 pair programming

**缺陷：**

- **功能单一**：专注协作，个人使用场景有限
- **需要服务器**：自建部署有运维成本
- **性能开销**：网络延迟影响终端响应
- **付费模式**：部分高级功能需要付费
- **稳定性待验证**：作为新工具，生产环境使用需谨慎

**适用场景**：远程团队协作、结对编程、技术培训

## 避坑清单

| 问题 | 解决方案 |
|------|----------|
| tmux 中文乱码 | 设置 `set -g default-terminal "screen-256color"`，使用 Nerd Font |
| tmux 复制到系统剪贴板 | macOS: `pbcopy`；Linux: `xclip`，配合 tmux 插件 |
| SSH 断线后 tmux 会话丢失 | 确认 tmux 在后台运行：`tmux new -d -s work` |
| iTerm2 触控板手势失灵 | 检查 Preferences > Pointer 是否启用 |
| tmux 与 vim 颜色冲突 | 设置 `set -g terminal-overrides "xterm-256color"` |
| cmux 无法启动 | 检查 tmux 版本是否 >= 3.0 |

## 选择建议

| 需求 | 推荐 |
|------|------|
| macOS 日常开发 | iTerm2（最省心） |
| 远程服务器运维 | tmux（必备技能） |
| 想用 tmux 但怕配置 | cmux（快速上手） |
| Linux 极客玩家 | otty（尝鲜 Rust 终端） |
| 团队远程协作 | Muxy（会话共享） |

## 总结

没有完美的终端工具，只有最适合你工作流的那一个。建议：

1. **新手入门**：从 iTerm2（macOS）或 tmux（Linux）开始
2. **进阶玩家**：tmux + 插件生态，打造个性化工作流
3. **团队协作**：在 tmux 基础上考虑 Muxy 进行会话共享
4. **尝鲜爱好者**：关注 otty 等新锐项目的发展

工具是为人服务的，花 10 分钟配置好你的终端，可能节省未来无数小时的工作时间。
